# UNAGI: правила работы на Windows и macOS

## Контекст и источник истины

- Общий репозиторий: https://github.com/Bazai9807/unagi_app.
- Пользователь разрабатывает Android на Windows, iOS на MacBook. Функции, дизайн, меню и правила заказа должны оставаться одинаковыми на обеих платформах.
- Сначала прочитай README.md и docs/HANDOFF.md. После существенных изменений обновляй docs/HANDOFF.md: что готово, что проверено, что осталось.
- Разговоры Codex между компьютерами не являются общим источником контекста. Решения и ограничения фиксируй в файлах репозитория; не предполагай наличие истории другого компьютера.

## Общий код

- `shared/www/` — исходник интерфейса и локальных демо-сценариев Android. По явному запросу владельца iOS реализуется нативно на SwiftUI в `ios/`.
- Не делай копий web-файлов внутри iOS. Общие данные и окончательные правила заказа должны приходить из backend API; клиентский расчёт не является источником истины.
- Android расположен в `app/`, iOS — в `ios/`.
- Каждое изменение оценивай для обеих платформ. Общее изменение делай один раз. Нативные различия обрабатывай в оболочках с одинаковым поведением для пользователя.
- Не заявляй о проверке iOS на Windows. Сборка iOS и проверка на симуляторе/телефоне требуют macOS и Xcode. Непроверенное явно записывай в HANDOFF.
- Сохраняй стабильные ID блюд и ключи `unagi.*` локального хранилища либо делай явную миграцию.

## Текущее ограничение продукта

- Пользователь разрешил разработку полной платформы. Актуальные требования — `docs/PLATFORM-REQUIREMENTS.md`; статус реализации — `backend/README.md`. Мобильное приложение пока остаётся офлайн-демо, backend разрабатывается отдельно в `backend/`.
- Не убирай пометки демо и не изображай приём рестораном, приготовление или доставку без настоящего серверного подтверждения.
- При будущей интеграции ключ iiko хранится только на HTTPS-сервере, никогда в клиенте или Git. Сервер проверяет цены, доступность, модификаторы и условия доставки; создание заказа должно быть идемпотентным.

## Git между компьютерами

- Перед началом проверь `git status`, текущую ветку и удалённые изменения. Получи `git fetch origin`; чистую основную ветку обновляй через `git pull --ff-only`.
- Для параллельной работы используй короткие ветки `codex/<задача>`, а не постоянные ветки для iOS и Android. Вливай законченные изменения в общую `main`.
- Не затирай чужие правки, не используй force-push и разрушительный reset. При расхождениях сначала изучи обе стороны.
- Изменения появятся на втором компьютере после commit/push и pull. Не обещай автоматическую синхронизацию незакоммиченных файлов или разговоров.
- Перед передачей работы выполни доступные проверки и запиши результат. Публикуй в GitHub, когда это входит в запрос пользователя; не оставляй работу только локально при явной просьбе синхронизировать.
- Не коммить секреты, локальные пути SDK, сертификаты, provisioning profiles, приватные ключи подписи, кэши и пользовательские снимки экрана.

## Проверки

- Backend: Node.js 24+, `cd backend`, `npm ci`, `npm run setup`, `npm test`, `npm start`. Локальные доступы в игнорируемом `.local-access.txt`; не переносить их в Git или документацию. Реальные заказы/платежи не включать до завершения интеграций и проверки восстановления после сбоев.
- Node.js 22+: `npm test` (без npm-зависимостей), `npm run preview` для проверки UI.
- Android: `./gradlew assembleDebug lintDebug` на macOS/Linux или `.\gradlew.bat assembleDebug lintDebug` на Windows; JDK 17+, SDK 36.
- Проверяй сценарий меню → корзина → оформление → история и сохранение после перезапуска при изменениях общего кода.
- Для iOS: `xcodebuild -project ios/Unagi.xcodeproj -scheme Unagi -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build`. После изменений проверяй локальное хранилище, safe area, клавиатуру и навигацию на симуляторе/телефоне.

# UNAGI — общий проект Android и iOS

Общий репозиторий для Windows и MacBook: https://github.com/Bazai9807/unagi_app.
Android уже реализован; нативное SwiftUI-приложение для iOS находится в `ios/`. Android использует `shared/www/`; iOS получает каталог и расчёт от общего backend API.

## Backend и кабинеты

В `backend/` добавлена серверная платформа и веб-кабинеты разработчика и бизнеса. Это работающий локальный прототип с базой данных, ролями, настройками, тестовыми заказами, аналитикой и счетами. Реальные заказы iiko, эквайринг и связь с мобильным приложением ещё не завершены. Инструкция запуска и точный статус: [backend/README.md](backend/README.md), контракт API: [backend/API.md](backend/API.md). Требования для обоих ноутбуков: [docs/PLATFORM-REQUIREMENTS.md](docs/PLATFORM-REQUIREMENTS.md).

## Начало работы на MacBook

```sh
git clone https://github.com/Bazai9807/unagi_app.git
cd unagi_app
npm test
npm run preview
```

Установите Node.js 22+ (для команд выше). Для iOS понадобятся Xcode и настройки подписи Apple. Откройте **корень unagi_app** в Codex. Для iOS откройте `ios/Unagi.xcodeproj` в Xcode; актуальные возможности и ограничения описаны в [ios/README.md](ios/README.md). История разработки — в [docs/HANDOFF.md](docs/HANDOFF.md).

GitHub передаёт файлы и коммиты; история бесед Codex и незакоммиченные изменения автоматически между ноутбуками не переносятся. Для последовательной работы перед началом получайте `git pull --ff-only`, после завершения — commit и push. Для одновременной работы используйте отдельные ветки задач `codex/<название>` с последующим объединением в `main`.

Структура:

```text
shared/www/     Общие экраны, стили, меню, корзина и оформление
app/           Android-оболочка, использует shared/www как assets
ios/           Нативное SwiftUI-приложение
tests/         Проверки общей логики
docs/          Контекст и передача работы между ноутбуками
```

Рабочая **демонстрационная версия** клиентского приложения суши-бара. По согласованию реальное веб-меню и iiko отложены: сейчас внутри 14 примерных блюд. APK работает полностью без интернета, не отправляет заказы и не принимает оплату.

## Возможности

- Категории, поиск по названию и ингредиентам, карточки блюд с составом и аллергенами.
- Собственные SVG-иллюстрации, встроенные в приложение; внешние картинки и CDN не нужны.
- Избранное и корзина с сохранением после закрытия.
- Доставка или самовывоз, количество приборов, проверка полей оформления.
- Примерный расчёт: минимум доставки 700 ₽, доставка 199 ₽, от 1 500 ₽ бесплатно. Самовывоз без минимальной суммы.
- Тестовое оформление, история последних 50 заказов, повтор заказа по текущему меню.
- Удаление локальных данных из профиля с подтверждением.
- Поддержка системной кнопки/жеста «Назад», адаптация под системные панели и клавиатуру.

**Все блюда, цены, пищевая ценность и условия — демонстрационные.** Адрес ресторана, зона доставки, часы работы, оплата, SMS, бонусы и статусы кухни ещё не подключены. Сохранённый тестовый заказ не означает приём заказа рестораном. Имя, телефон, адрес и комментарий не сохраняются в истории.

## APK

`artifacts/unagi-demo.apk` — подписанная debug-сборка для непосредственной установки на телефон. Android 8.0 и новее; протестирован запуск на Samsung SM-S942B, Android 16.

Это сборка для проверки, а не для публикации в магазине. Для релиза нужен собственный постоянный ключ подписи владельца проекта. Debug-ключи не включены в репозиторий.

## Сборка и установка

Нужны JDK 17+ (можно JBR из Android Studio), Android SDK 36 и Node.js 22+ для тестов. Gradle 8.13, Android Gradle Plugin 8.13.0. Само Android-приложение не использует сторонних runtime-зависимостей.

```powershell
# Сборка (пути Android Studio/SDK определяются автоматически)
.\scripts\build.ps1

# Установка на единственное подключённое устройство
.\scripts\build.ps1 -Install

# При нескольких устройствах
.\scripts\build.ps1 -Install -Serial <серийный-номер-из-adb-devices>

# Проверки
npm test
.\gradlew.bat lintDebug

# Проверка интерфейса в браузере: http://127.0.0.1:4173
npm run preview
```

На телефоне должны быть включены параметры разработчика, отладка по USB и разрешён доступ для компьютера. При обновлении `adb install -r` сохраняет данные установленного приложения с той же подписью.

## Архитектура

После переноса в общую папку 20 сентября 2026 проверены: 5/5 тестов, успешные `assembleDebug lintDebug` и совпадение всех шести web-ресурсов APK с `shared/www` по SHA256. iOS пока не реализован и не проверен.

- `app/src/main/java/ru/unagi/mobile/MainActivity.java` — Android Activity и защищённый WebView. Локальные ресурсы обслуживаются через `https://app.unagi.local`, файловый доступ и чужая навигация запрещены. JavaScript bridge отсутствует. Разрешение INTERNET не запрашивается.
- `shared/www/menu.js` — источник демонстрационного меню; точка замены на API-репозиторий.
- `shared/www/domain.js` — расчёт корзины и валидация.
- `shared/www/app.js` — интерфейс, состояние и тестовые заказы.
- `shared/www/art.js` — SVG-иллюстрации.
- `tests/domain.test.cjs` — проверки пограничных сумм, количества, недоступных блюд, телефона и оформления.

Локальное хранилище WebView: корзина, избранное, способ получения, последние 50 тестовых заказов. Автоматическое резервное копирование Android отключено. Данные гостя не синхронизируются между устройствами.

## Следующий этап: iiko

Нужен отдельный HTTPS-сервер. API-ключ iiko нельзя встраивать в APK или клиентский JavaScript.

1. Получить параметры конкретного заведения: доступ к iiko, организацию, терминальную группу, внешнее меню/тип цен, способы получения и оплаты.
2. Настроить на сервере получение меню с реальными ID, фотографиями, размерами, модификаторами и доступностью. Заменить `UnagiMenu.load()` на запрос к этому серверу.
3. Перенести окончательный расчёт на сервер: цены, обязательные модификаторы, стоп-листы, зоны и часы доставки, минимумы, стоимость доставки. Повторно проверять всё перед отправкой.
4. Заменить локальную ветку `submitOrder()` созданием реального заказа через сервер. Использовать ключ идемпотентности, чтобы повторное нажатие/тайм-аут не создали дубликат. Различать «принят запрос», «создан заказ» и «ошибка».
5. Подключить фактические статусы iiko. Не имитировать приготовление/доставку таймерами. Обрабатывать неопределённый результат при потере связи.
6. После настройки заведения добавить реальную политику обработки данных, контакты, согласия, способы оплаты и при необходимости SMS-вход. Для платежей — провайдер и подтверждения на сервере; не хранить реквизиты карт.
7. Добавить разрешение INTERNET и строго ограниченный серверный origin/CSP, интеграционные тесты на тестовой организации. Только после этого включать реальные заказы.

Рабочего подключения iiko в этой версии нет. Ресторан не получал тестовые заказы.
